# Image Format Readiness Design

## Outcome and boundary

Inspect one exported HTML document and the local images it names. Report byte-budget, intrinsic-dimension, aspect-ratio, format-policy, alternative-text, and loading-declaration observations without rewriting an original. This is a local-file reporter, not a browser, image decoder, optimizer, network fetcher, or statement about current browser versions.

The CLI takes `--root DIR --html FILE --matrix FILE [--report FILE]`, where the inputs resolve inside the real root and an optional report destination is confined under it. It reads local image sources only. `--json` suppresses the human summary on stderr. Stdout is always the JSON report; a safe report file receives byte-identical JSON. The library exposes `TOOL_ID`, `RULE_SEVERITY`, `checkImageReadiness({root, html, matrix, limits?, now?})`, and `exitCodeFor(report)`.

## Evidence flow

1. Validate CLI/library options and bounded positive integer limits. The required local matrix is configuration: it has exactly `schemaVersion: "1"`, an opaque visible `matrixId`, and 1–16 browser rows, each with a visible unique browser/version ID and a unique subset of `png`, `jpeg`, `gif`, `webp`. A malformed, duplicate-key, unreadable, or out-of-root matrix is invalid configuration and exits 2 with empty stdout. The shipped example matrix is a pinned policy fixture, not a live-current browser-support assertion. An HTML or image file that could not be read, decoded, confined, or interpreted returns an `incomplete` report and exits 2.
2. Resolve the real HTML path under the real root; read at most `maxHtmlBytes + 1` bytes and decode strict UTF-8. An unavailable HTML file is not a zero-image pass.
3. Scan the bounded HTML subset deterministically for `<img>` start tags, skipping comments and raw `<script>`/`<style>` bodies. Quoted and ordinary unquoted attribute values are supported. Duplicate relevant attributes, malformed tags, `<picture>`, `<source>`, `srcset`, templates, and image sources the scanner cannot map to a local path make the run incomplete. A non-image `<img` string in a comment or script is not a reference. The scanner does not claim complete HTML5 parsing.
4. Each `src` is a relative or root-relative local path with ordinary path characters. External, data, protocol-relative, entity-encoded, query-bearing, fragment-bearing, and percent-encoded sources are unsupported evidence, never fetched or silently ignored. Resolve the real image path under the real root, including symlinks, before reading. Outside-root links are incomplete.
5. Read bounded headers and identify PNG, JPEG, GIF, and WebP by bytes, not extension. Extract positive intrinsic dimensions from PNG IHDR, GIF logical screen, JPEG SOF, and WebP VP8/VP8L/VP8X headers. A malformed or unknown header is incomplete; successful header inspection is not a full decode or integrity check. Read-only byte size comes from the local file stat. Cache metadata by canonical file path, but assess each HTML reference's alt/loading/dimension attributes independently.
6. Compare positive integer HTML `width` and `height` with intrinsic width and height by exact integer cross-product (`BigInt`). Missing either attribute yields `intrinsic-dimensions-undeclared`; a different ratio yields `aspect-ratio-mismatch`. `alt` is required, but `alt=""` is a legitimate decorative declaration. `loading="eager"` and `loading="lazy"` are accepted. Missing loading is an informational declaration finding; unsupported values are incomplete rather than guessed.
7. Apply only the supplied, explicitly versioned local browser-format matrix. Its rows govern whether a parsed format gets `format-not-in-matrix`; the report names the matrix ID and browser row IDs, not an inferred current compatibility state. No browser is contacted. Per-image and total unique-file byte budgets are inclusive; N is allowed and N+1 fails. No original file is written.
8. Before a requested report write, use the catalog write guard with the real root and the complete named input set: HTML, matrix, and every local image path the scanner stats, attempts to resolve, or reasons about, even if that image is unreadable or points outside the root. Refuse a destination symlink, escaping parent, hard link to any input, direct input path, or one/two-hop dangling input alias to a new destination. A distinct missing image does not prohibit a safe report. A refusal exits 2 with an incomplete report on stdout and leaves every original untouched. A safe new or existing regular report file receives exactly the stdout bytes.

## Limits and report

Default parser limits: matrix 64 KiB, HTML 1 MiB, image references 500, header bytes per image 256 KiB, findings 500, cooperative elapsed time 30,000 ms. Configurable byte budgets default to 250,000 per unique image and 2,000,000 total unique bytes. Every bound has an exact-N and N+1 test. `now` is an injected function, defaulting to the `Date.now` function reference only when not supplied. Elapsed-time expiry is incomplete, never a pass or a semantic failure.

The report follows the house envelope with `schemaVersion: "1"`, `tool`, `status`, `summary.checked`, errors/warnings/info counts, deterministic findings, and a per-reference `images` section containing only bounded root-relative paths, observed header format/dimensions/bytes, and safe declarations (`altPresent`, `altEmpty`, loading enum, numeric declared dimensions). It never emits alt text or other page prose. Findings sort by UTF-16 code units on file, pointer, rule ID. All untrusted diagnostic strings are bounded and stripped of C0, DEL, C1, line/paragraph separators, and bidi controls. A value that renders empty cannot satisfy a required field.

`status: incomplete` outranks known failures whenever any required evidence is missing. A fully inspected oversize image, missing dimensions, missing alt, aspect mismatch, or pinned-matrix format gap is a proven failure. No image references is `no-images` incomplete, not a vacuous pass. The README will state the rule/severity table, fixed matrix, limits, exit shapes, unsupported HTML forms, and non-goals.

## Verification

Tests drive the good ordinary `<img>` case first, then the oversized image and missing dimensions through the real CLI. Additional tests cover byte/dimension boundaries, malformed images, all supported header formats, comments/script false references, every unsupported source form, root symlink escape, pinned matrix validation and behavior, alt/loading declarations, no-image and unreadable input, deterministic/code-unit finding order, injected timeout N/N+1, and originals preserved. Report-write tests cover safe new/existing files and byte equality with stdout, direct aliases, destination symlinks, escaping parents, hard links, and one/two-hop dangling image aliases, with a distinct missing-image control. Every README guarantee gets a named test observed failing when its production guard or rule is removed.
